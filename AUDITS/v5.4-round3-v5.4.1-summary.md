# Anti-Hallucination Protocol v5.4 Round 3 -> v5.4.1 synthesis

Date: 2026-08-09

This synthesis adjudicates the v5.4 standalone-repository audit round that directly informed v5.4.1.

## Evidence classes

The reports are not averaged by model count.

1. **Fresh-clone execution** - strongest for executable properties and actual test inventory.
2. **Execution on supplied project files** - useful, but weaker when the materialized snapshot is incomplete or differs from Git HEAD.
3. **Static/source/cross-component audit** - can establish deterministic code paths from source, but must not claim an unexecuted reproducer was executed.
4. **Methodology review** - evaluates audit procedure, not repository correctness.

A minimal reproducer plus actual output outranks model consensus.

## The 92-vs-102 test conflict

This conflict is resolved in favor of the fresh-clone evidence.

- Big Pickle: 102 collected, 100 PASS, 2 FAIL.
- DeepSeek V4 Flash: fresh standalone clone, 102 collected, 100 PASS, 2 FAIL.
- GLM 5.2: 92/92 PASS on Project Files, explicitly not a fresh git clone and with some reference content unavailable/placeholder-backed.

Therefore the v5.4 release test inventory is **102**, and the canonical v5.4 baseline before patching was **100 PASS / 2 FAIL**.

Both failures were test-contract defects, not integrity-checker defects:

1. `description: Test fixture [` is valid YAML plain-scalar content; the old test incorrectly expected a YAML parse error.
2. The old `metadata.hermes` scalar fixture was itself malformed YAML because nested `tags:` remained below a scalar; the parser correctly failed earlier than the asserted mapping-type message.

v5.4.1 fixes the fixtures instead of weakening the checker.

## Findings intentionally not promoted to release blockers

### Behavioral obedience benchmark

Still absent. This remains a roadmap validation gap, not an implementation defect, because the project explicitly does not claim that Markdown instructions are obeyed under long-context/runtime pressure.

Status: `BENCHMARK`.

### Real-world source independence

v5.4.1 rejects internal contradictions visible in the record, such as the exact same declared source or source identity placed in two allegedly independent groups. It still does not infer hidden common upstream provenance.

Status: `SEMANTIC / EXTERNAL OBSERVATION`.

### Old current-state timestamps

The structural checker validates the timestamp profile and future-time impossibility. It does not impose one universal max-age because freshness is claim-specific and already represented by `freshness=CURRENT_ENOUGH`.

Status: `KEEP CLAIM-SPECIFIC`.

### RFC3339 leap seconds

The local parser implements a documented RFC3339-profile useful for this evidence contract rather than every rare RFC3339 edge. v5.4.1 updates wording to avoid claiming more parser coverage than exists.

Status: `DOC PRECISION`, not a false-positive blocker.

### Command-output memory ceiling

`max_output_bytes` limits what output may be accepted as evidence after capture; it does not bound subprocess memory during `capture_output=True`. This is a robustness improvement opportunity, not a false verification path under the stated contract.

Status: `DEFER`.

### Legacy battery with zero attempted probes

Legacy scripts are explicitly outside the portable v5.4.1 correctness/liveness contract and read-only by default. A future cleanup may make zero-attempt execution nonzero, but it does not block the portable release.

Status: `DEFER LEGACY`.

## CI evidence for v5.4.1 candidate

A permanent GitHub Actions regression workflow was added for Python 3.11 and 3.13.

During hardening, the first CI run correctly exposed one stale positive test fixture: two different sources inherited the same default `source_identity`, so the newly strengthened invariant rejected the record. The fixture was corrected to represent genuinely distinct declared identities.

After that correction, GitHub Actions produced a green run with:

- 116/116 tests passing on Python 3.11;
- 116/116 tests passing on Python 3.13;
- integrity PASS;
- offline research provenance PASS;
- portable liveness PASS.

A later final-head CI run after release/version/research documentation changes also completed successfully in both Python matrix jobs with every configured step green.

This establishes the repository's checked deterministic contracts. It does **not** establish semantic truth, real source independence, exhaustive search, or behavioral LLM obedience.

## Methodology correction for the next audit round

GPT-5.6 Sol correctly identified a contamination flaw in the earlier audit prompt: asking an auditor to read `AUDITS/**` before a supposedly independent novel hunt destroys independence.

Future audits should use:

```text
FRESH CLONE
  -> inventory AUDITS filenames/hashes only
  -> read implementation/docs/tests excluding historical audit contents
  -> baseline execution
  -> prompt-mandated probes
  -> genuinely novel hunt
  -> only then read AUDITS/**
  -> historical reconciliation
```

Prompt-mandated probes and agent-invented probes should be counted separately.

## v5.4.1 release judgment

v5.4.1 is a **hardening patch**, not a new protocol architecture.

It preserves:

- the seven-rule hot path;
- T0-T3 risk scaling;
- explicit evidence states;
- progressive disclosure;
- structural-vs-semantic boundary;
- non-automatic Hermes helper model.

It closes the reproduced/static deterministic gaps from the v5.4 audit round and adds permanent CI.
